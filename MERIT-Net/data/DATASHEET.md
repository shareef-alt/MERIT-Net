# MANET-FLOOD: an AODV flooding-attack dataset with local per-neighbour features

A labeled dataset for intrusion detection in mobile ad hoc networks (MANETs),
generated in **NS-3 3.44**. Unlike flow-based IDS datasets, every record is a
**local, per-neighbour, per-window observation** — what one node can see about
one of its neighbours in one 1-second window — which is what on-node MANET
detectors (including mobility-aware ones) actually operate on.

Released under CC-BY 4.0. Generated with the open scenario in this package
(`meritnet-scenario.cc`, `dataset_gen.py`); regenerate or extend it by rerunning
the grid.

**This release:** 168 NS-3 runs = 6 attack conditions x 5 speeds (0,5,10,15,20
m/s) x 6 seeds, 50 nodes, 200 s each — about 618,000 labeled per-neighbour
records (class balance: benign 338k, rreq 94k, hello 48k, data 92k, syn 47k).
12 of the intended 180 runs (seeds 4 and 5 at 5 and 20 m/s) are absent: those
specific mobility seeds trip an NS-3 internal assertion for every attack
including benign, so they were skipped rather than worked around. The grid is
resumable — add seeds or node densities with `dataset_gen.py` and the dataset
grows in place.

## Motivation
Public flooding datasets are either wired flow captures (CICDDoS2019, NSL-KDD) or
static-WSN datasets (WSN-DS), none of which contain AODV route discovery, node
mobility, or per-neighbour local observation. MANET-FLOOD fills that gap so that
detectors relying on route-discovery and mobility signals can be trained and
compared on realistic data.

## Network and simulation
- Simulator: NS-3 3.44, AODV routing, IEEE 802.11b, Yans channel, log-distance
  loss (exponent 3), transmit power tuned to a ~250 m range.
- Field: 1000 x 1000 m; nodes: 50 (configurable 20-200).
- Mobility: random waypoint, max speed {0, 5, 10, 15, 20} m/s, 1 s pause.
- Benign traffic: 20 on-off CBR/UDP flows (16 kb/s) + several long-lived TCP
  connections between random honest nodes.
- Duration: 200 s per run; attacks begin at t = 60 s.

## Attacks (one per run, labeled)
| Label | Attack | How it is produced | Intensity |
| --- | --- | --- | --- |
| 0 | benign | honest traffic only | — |
| 1 | rreq | attacker repeatedly requests routes to nonexistent addresses, so AODV floods RREQs | 20 /s |
| 1 | rreq_stealth | same, but toward real node addresses (hides the unknown-destination signature) | 20 /s |
| 2 | hello | attacker's AODV HELLO interval shortened and transmit power raised | 20 /s |
| 3 | data | a colluding attacker pair exchanges high-rate UDP through honest relays (sleep deprivation) | 40 pkt/s |
| 4 | syn | attacker opens many TCP connections to a victim without completing them | 20 /s |

Attacks are standard simulated traffic/configuration, not real-world exploit
code. Attacker node ids are recorded per run.

## Features (23 per record)
Order matches the model code (`F_RREQ=0 .. F_MASK=22`):

- **Traffic counts** (sniffed): RREQ, HELLO, DATA, SYN, RERR, COMP (handshake
  completions), FB (TCP feedback/ACKs).
- **Topology / mobility**: DEGJ (neighbour's degree), DEGI (observer's degree),
  CHURN (neighbour-set change), LINKAGE (link age, normalised), DDIST (distance
  change), NEWFLOW, ACTFLOW (active flows).
- **RREQ symptoms**: UNKNOWN (share of requests for nonexistent destinations),
  ENTROPY (destination entropy), DUP (duplicate ratio).
- **Other symptoms**: HSYM (HELLO link symmetry), PERFLOW (packets per flow),
  FBRATIO (feedback ratio), HALFOPEN (unmatched-SYN ratio).
- **MASK**: 1 if the observer had the neighbour in range this window.

Traffic counts are from promiscuous sniffing with AODV/IP/TCP header parsing;
topology features from node positions; RREQ symptoms from sniffed destinations.

## Files and format
- `raw/<attack>_v<speed>_n<nodes>_s<seed>.npz` — full `(T, N, N, 23)` float16
  tensor `X`, plus `attackers`, `label_j` (per-node class), `speed`, `attack`,
  `astart`.
- `manet_flood.csv` — flat rows: `attack, speed, nodes, seed, window, observer,
  neighbour, label, <23 features>`. Honest records subsampled (2%); all attacker
  records after attack start kept. Use the `.npz` tensors for sequence models.

A record's label is the neighbour's attack class after t = 60 s, else 0.

## Suggested splits
Train / validation / test on **disjoint seeds**; for a generalization test, train
on one speed or mobility model and test on another. Low-rate and stealthy
attacks can be held out entirely to test unseen-attack detection.

## Known limitations
- Topology features use ground-truth positions (a node's true neighbour set); a
  deployment would estimate these from HELLOs. Detectors that must be fully
  passive should rely on the sniffed and symptom features.
- Single attacker (two for the data flood) per run by default; multi-attacker and
  collusion variants can be generated by extending the attacker list.
- One attack type per run, to keep labels unambiguous.
